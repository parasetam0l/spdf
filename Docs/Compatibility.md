# Compatibility and supported workflows

Rendering a PDF does not imply that every element can be edited. sPDF preserves unsupported content during unrelated operations and refuses transformations it cannot verify.

| Area | Supported behavior | Limits |
| --- | --- | --- |
| Reading | Native rendering, navigation, outlines, search, and selection | Owned extraction and selection do not cover every font or nested content stream |
| Existing text | Direct page caret, block dragging, character formatting and saved authoring boxes; verified paragraph reconstruction with mixed styles, supported embedded TrueType and simple Type 1C CFF fonts, horizontal Identity-H subsets and bounded spacing adjustments | See [Daily Use](Daily-Use.md) for the supported paragraph profile. Fully visible embedded-font text within a shared rectangular clip retains that boundary during editing and saving; overflow blocks committing. Bullet and simple numbered-item boundaries prevent neighboring items from merging; separately painted markers retain their original position. Eligible TrueType fonts installed through the app's license-acceptance flow can be chosen and embedded as subsets; missing glyphs and disallowed embedding are refused. Variable fonts embed only their static default instance; non-default named/coordinate instances, CFF2 and unsupported composed transforms refuse with explicit reasons. Supported composed page-space transforms are horizontal text, bounded horizontal synthetic-italic shear, and pure rotation with positive uniform scale; non-uniform scale, vertical shear, mirror/flip, excessive shear and rotation-plus-shear refuse. Bidirectional Hebrew/Arabic/Devanagari paragraphs are shaped with Core Text and embedded as whole TrueType programs with logical copy/search text (bounded UAX #9: no isolates or bracket-pair resolution); horizontal CJK wraps with kinsoku rules and vertical CJK columns use Identity-V with declared punctuation rotation (CJK-only vertical input). Arbitrary system-font embedding, custom variable axes, document-wide reflow and layout outside that declared profile are not provided. Automatic list layout/numbering, arbitrary clipping, partly hidden text, complex shaping, unsupported CFF encodings, rotated/skewed text and uncertain layout remain restricted |
| Images and graphics | Placement edits, copy-on-write edits of nested/transformed image instances, replacement/import with mask and colour-space preservation, explicitly named RGB conversion, per-instance external-editor round trips with previewed reimport, ordinary page-level vector path style/transform edits, page-object arrange/align/distribute/paint-order with group/group support (Objects > Arrange Objects), supported masks and transformations, added text and shapes | Uninspectable paint, unsupported codecs, and ambiguous shared resources can restrict an operation; partial form coverage, shared local matrices and rotated outer transforms refuse with reasons |
| Pages | Rotation, reorder, insertion, import, extraction, deletion, headers/footers/page numbers/watermarks and Bates numbering with reference checks, a thumbnail organizer with one-undo batch operations, Replace Pages with an explicit retention matrix, and PDF creation from images/text/clipboard with page size/orientation/margins | Complex destinations, forms, tags, and signed input may require refusal or explicit conflict handling. Applied sPDF mark sets can be updated in place or removed as a unit; unrelated content and other sets are preserved. Bates batch numbering skips encrypted or signed inputs and discloses digit-width overflow |
| Review | Markup, notes, free text, shapes, ink, stamps, replies, review state, printable review summaries, portable comparison reports, comparison scope presets with repeated-page mapping audit/manual overrides, and scan/layout qualification with explicit raster evidence and uncertainty | Unsupported actions remain inert; drawn signatures are visible marks, not cryptographic signatures. Reports are local, never mutate the source, and bound their size (400 comments/250 pages for summaries; 2,000 changes/300 pages for comparisons). Report body text uses standard-14 WinAnsi with a labelled UTF-8 hex appendix for other characters; missing images fall back to page outlines or an explicit note; comparison region crops are orientation approximations while recorded page-space bounds are authoritative |
| Forms | Common AcroForm filling, appearances, authoring, field properties and value exchange; local form-response collection into a review table with CSV/XLSX export (conflicts/missing/duplicates visible; sources untouched); accessible validation with focus/screen-reader flow and lifecycle qualification; portable values-only form-data round trip with unsupported external actions identified; declarative app-specific sum/format rules stored as static /V values plus generated appearances (freeze in one undoable step); rich runs with bounded RTF /RV, mixed-run appearances, comb/multiline/long-value handling, inherited properties and embedded TrueType appearance fonts | XFA is not editable; document JavaScript is never authored or executed; imported actions (/AA, /A, /CO) are detected, preserved and disclosed but their external behaviour is not claimed; accessible validation reports required-field errors with focus/page-read-order targets and screen-reader announcements, read-only declared show/hide rules, reset; lifecycle qualification runs on copies and distinguishes passed/failed/not-exercised combos (fill -> page operations -> save -> sign/flatten/export); run-level embedded fonts, CFF outline fonts, restricted-permission fonts and missing glyphs refuse |
| OCR | On-device recognition, searchable layers, suspect-word review/correction, previewed scan cleanup (deskew/orientation/crop/contrast/background with selective application and recoverable source scan), one-word editable scanned-text reconstruction, and a deterministic language/layout quality harness (grapheme CER, WER, reading-order agreement, line-overlay IoU); mixed scanned/digital pages get bounded generated layers that avoid duplicate digital text and can replace only the chosen layer without restoring redaction-removed content | Recognition quality and available languages depend on Apple's services and the source image; the matrix reports synthetic-input measurements separately from real consented corpora, and no engine/language/settings change is made |
| Protected documents | Standard-security authentication and permission-aware editing/saving | Unsupported handlers refuse; signed/protected files never silently become unsigned or decrypted |
| Signatures | Inspection and supported signing from a keychain identity; RFC 3161 timestamp requests/verification and OCSP/CRL revocation evidence with offline trust by default; certification (P1-P3 DocMDP) and FieldMDP lock authoring as the first signature of an unsigned/unencrypted document; status reports for permissions, field locks and later changes; documented review/approval/publish workflows per signer; explicit Keychain/Secure Enclave/hardware-token/PKCS#12 identity selection (certificate-only imports cannot sign); reusable AES-256 security presets with policy reports; signature presentation separating visible certificate signatures, hidden certificate signatures and visible graphical marks | Trust, timestamp, revocation and long-term evidence stay distinct; timestamp/revocation network access is explicit and allow-listed, never background, and failure is unavailable (never valid); certification authoring refuses existing DocMDP/encryption/signatures and sPDF still permits new fields under P3 (documented profile extension); offline long-term validation reads embedded /DSS evidence and classifies B-LT/B-LTA only for the disclosed single-gap ByteRange subset (incremental append-DSS/document-timestamp writers exist; /UR, network-fetched evidence and multiple ByteRange gaps report incomplete/unsupported, never valid); reusable security presets write AES-256 V5/R6 only and certificate-recipient encryption is deliberately absent; other tools' later edits are detected, not prevented |
| Redaction | Reviewable pending marks (text, rectangles, whole pages) before apply, search-based redaction with reusable term sets and patterns, supported content removal, separate sanitized copies, selective hidden-data review/sanitization (metadata, comments, links, form values, attachments, actions, layers, alternate text, OCR layers, thumbnails, /ID, unreachable objects, earlier revisions) and independent adversarial output validation; replacement reason codes, painted overlays/replacement text, repeated-page-region staging, and OCR-over-raster matches that remove the whole intersecting scan with explicit disclosure | Staged marks change no bytes and the save barrier warns before saving unapplied marks; applied removal is one atomic secure rewrite. Text marks are glyph-precise for inspectable runs; images/vector/form paint need region or whole-page marks, and text-over-scan matches remove the whole intersecting raster draw (disclosed). Any content that cannot be inspected and removed safely causes refusal |
| Tagged PDFs | Structure inspection and explicit supported repairs/edits; tag-tree create/delete/group/split/reparent, ActualText/language/artifact controls and independent visual reading-order editing (Accessibility > Structure and Reading Order…); reviewed assisted tagging for headings/paragraphs/multicolumn paragraphs/lists/figures/captions/header-footer artifacts with explicit untagged accounting and reviewer correction (Accessibility > Assisted Tagging…); accessible table relationships (TH scope, /Headers associations, spans, summary) and form labels/tab order with a screen-reader-shaped transcript (Accessibility > Accessible Tables and Forms…); accessible reading model/reflow/high-contrast audit with tag-preservation verification (Accessibility > Accessible Reading…); DOCX reconstruction qualification by document class with separate text/editability/structure/rendered-layout scores (Tools > DOCX Reconstruction Qualification…) | No blanket PDF/UA conformance claim; VoiceOver and intended Office applications are not launched automatically, rendered-layout scores are local proxies and manual steps stay attached; synthetic fixtures are not a corpus |
| Exports | Text, images, HTML, DOCX, tables, attachments, printing; reviewed table CSV/XLSX export with reviewed boundaries/spans/header/continuation and a review report; deterministic PowerPoint (PPTX) reconstruction with editable text/images/shapes where the declared profile supports them, clearly labelled full-slide raster fallback elsewhere and an editability report | See the fidelity limits in [Exports](Exports.md); the PPTX is a reconstruction (exact layout/fonts/line-breaking not reproduced) and was not opened in Office by the app; table export operates on extracted/reviewed tables, not new recognition |
| Automation and scripting | Declared spdf-automation-v1 profile shared by a user CLI, App Intents/Shortcuts and an AppleScript bridge; stable operations/options, exit codes and JSON/text envelopes; batch recipes with resilient execution; watched folders with explicit folders/recipes, atomic settle detection, persisted exactly-once state, loop prevention and visible failures | Automation exposes only declared operations (no arbitrary scripts/JS/network/OCR/signing), writes never overwrite inputs, encrypted inputs require an explicit password, and watched folders scan selected folders one level with no daemon or automatic retries |
| Print production | Read-only preflight checks; configurable preflight rule sets with severities, object/page navigation, exact staged-fix previews and affected-check reruns; declared-conformance PDF/A-1b/A-2b/A-3b conversion (deterministic XMP, sRGB output intent, profile-specific content rules, saved bytes published only after a compliant veraPDF verdict); declared-subset PDF/X-4 and PDF/X-1a:2003 export (nested page boxes, embedded fonts only, one declared CMYK output intent with embedded ICC, identification XMP, annotation/form flattening, x1a transparency/RGB refusals) with saved-byte verification and an independent qpdf-JSON validator; colour-managed conversion via public CoreGraphics APIs (RGB/gray/CMYK/Lab/ICCBased sources, all rendering intents, declared BPC/black preservation, output intents only when conversion occurred); owned separation/overprint preview with process/spot plates, coverage, overprint/knockout counts and explicit accuracy boundaries; quality optimization with lossless/print/web/smallest presets, per-resource DPI/byte plans, refusal instead of flattening and measured preservation verification | No blanket PDF/A, PDF/X or ISO certification claim; the CMYK output condition is sPDF-declared (not SWOP/Pantone colorimetry); colour conversion is image-only with explicit source refusals; separation/overprint is an owned declared approximation (no third-party print-reference agreement); linearized/fast-web output is explicitly not supported (ordinary saves are non-linearized and byte-correct, with reconnaissance and acceptance plan recorded); validator-unavailable or failed conversions produce no conforming bytes and never a conforming label |

The native app currently limits source snapshots to 256 MiB. Parsing, stream decoding, traversal, and export paths have separate bounded budgets. Larger or unsupported documents can fall back to restricted viewing.

Single-byte text supports WinAnsi and PDF MacRoman encodings, including explicit glyph overrides and Unicode maps. Replacements must map back to the intended characters using the existing font. Undefined codes and missing subset glyphs refuse substitution. Encoding support alone does not establish that a paragraph's layout can be edited safely.

Untouched documents retain their original bytes. Eligible edits to classic cross-reference files use incremental saves. Sources using cross-reference streams use a verified full rewrite when edited, so the saved document remains readable in Apple's renderer. Unsupported signatures and protection states retain their separate save restrictions.

Object-stream collections are accepted with checked references and bounded, acyclic links. Editing a linearized PDF saves a normal PDF with stale, unreferenced fast-web-view hints removed; the original file is preserved until Save. Referenced hints, signatures and protection keep their separate restrictions.

Signed releases, clean installation, and Sparkle update behavior require live verification in addition to automated tests.
