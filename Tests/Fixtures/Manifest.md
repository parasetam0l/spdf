# Original fixture provenance

All fixture bytes are generated deterministically by our Swift `PDFFixtures` target and `spdf-fixtures` tool, except the published encrypted test vectors under `Encrypted/` and the DejaVu font subsets described below. They contain original synthetic text/graphics and no personal data, copied document content, external images, or personal font assets. The generated font fixtures embed licensed DejaVu subsets, with their license in `DejaVu-LICENSE.txt`. Standard PDF Helvetica is referenced by name. Original generated fixtures use the project MIT license. Imported test vectors and font subsets retain their respective Apache 2.0 and DejaVu licenses.

## Signed fixtures (test-only)

Generated by `python3 Scripts/make-signed-fixtures.py` with openssl as an independent CMS producer; regenerate only when the profile changes. The script also writes the test CA and signer certificates. These files are used only by the signature tests and the smoke run.

| File | Expected semantics | Supported proof |
|---|---|---|
| Signed/signed-one-page.pdf | One page with a `Signature1` field; detached CMS (RSA PKCS#1 v1.5, SHA-256) over the whole file with a reserved 8192-byte /Contents | Inventory, ByteRange validation, digest and signature verification, trust with the test CA as an explicit anchor |
| Signed/signed-then-updated.pdf | The signed file plus an incremental revision that adds `/Rotate 90` after signing | Signature still cryptographically valid; unsigned changes reported with the changed-object count |
| Signed/signed-sha1.pdf | The same skeleton signed with SHA-1 | Reported as indeterminate (unsupported digest), never valid |
No key material is committed: the validation tests take their trust anchor from the CA certificate embedded in each fixture's CMS chain, and the signing tests generate throwaway keys, certificates, and a PKCS#12 with openssl at test time and import the identity into a temporary keychain. The generator script keeps its keys in a temporary directory.
